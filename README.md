# Зачётка — единый проект

Сайт для совместной подготовки к сессии: архив материалов, билеты, случайный билет, помодоро-таймер, персональный прогресс и учебные группы. Python 3.10+, Django 5.2, Bootstrap/собственные CSS.

## Что объединено

За основу интерфейса взята актуальная зелёная тема репозитория. В одной кодовой базе связаны функции из рабочих веток:

- `2.5-materials-list`, `3.8-materials-fetch`: список материалов, избранное (теперь сохраняется на сервере);
- `2.9-designer-style`, `3.7-timer-fetch`, `3.7-my-sessions`, `4.3-total-frontend-clear`: помодоро, сохранение остатка, завершённые сессии, история/график;
- `3.5-tickets-and-sessions`, `3.6-tickets-backend-integration`, `3.6-subject-progress-backend`, `4.3-total-frontend-clear`: чек-лист, оценки билетов, готовность предмета, случайный билет;
- `3.9-profile-fetch`: изменение учебной группы через fetch (в этой версии только на существующую группу);
- новые требования: авторизация перед архивом и скачиванием, скрытие через админку, 20 МБ, фильтры, ежедневное резервирование.

**Это единая интегрированная кодовая версия**, а не механическое слияние независимых веток. Незавершённые фронтенд-заглушки заменены работающими API. Не нужно копировать ещё какие-то файлы из веток.

## Запуск на Windows

```powershell
git clone https://github.com/cnn13/zachetka.git
cd zachetka
# Замените файлы репозитория файлами из этого ZIP, затем:
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Сайт: <http://127.0.0.1:8000/>. Админка: <http://127.0.0.1:8000/admin/>.

Для создания администратора укажите пароль **через переменную окружения**, а не исходники. Логин по умолчанию `admin676967`:

```powershell
$env:ADMIN_PASSWORD = Read-Host 'Пароль администратора'
python manage.py bootstrap_admin
Remove-Item Env:ADMIN_PASSWORD
```

В Linux/macOS:

```bash
read -rsp 'Пароль администратора: ' ADMIN_PASSWORD; echo
export ADMIN_PASSWORD
python manage.py bootstrap_admin
unset ADMIN_PASSWORD
```

**Пароль, переданный в задании, не публикуется в коде публичного репозитория.** При каждом запуске `bootstrap_admin` создаёт или обновляет администратора в существующей БД.

## Данные не должны пропадать

- Пользователи, группы, билеты, оценки, избранное, завершённые сессии и метаданные файлов хранятся в базе данных.
- Локально SQLite — `db.sqlite3`. Не удаляйте этот файл при обновлении.
- На сервере задайте постоянный `DATA_DIR` либо PostgreSQL через `DATABASE_URL`; файлы храните на постоянном `MEDIA_ROOT`.
- Если сервер стирает свои файлы после деплоя, **одного исходного кода недостаточно**, чтобы сохранить данные. Подключите диск/БД с сохранением между релизами.
- Ежедневный backup создаёт `scripts/backup.py`, после ручного добавления в cron/планировщик; хранит семь последних копий.

**Обновление уже работающего сайта:** сначала сделайте backup БД/media, затем замените исходники и выполните `python manage.py migrate`. Пользователи из прежней БД останутся. Если старая БД исчезла на хостинге, новые исходники не смогут её восстановить без резервной копии.

## Основные функции

- `/materials/` — архив только после входа. Поиск и одновременная фильтрация по предмету, преподавателю, курсу и году. Избранное сохраняется отдельно для каждого пользователя.
- `/materials/<id>/file/` — защищённый просмотр и скачивание. `/media/` специально **не раздаётся напрямую**.
- В `/admin/materials/material/` есть `Скрыт`; скрытый материал возвращает 404 и не попадает в фильтры/архив.
- `/tickets/` — личные оценки «Не знаю», «Плохо», «Выучил», процент готовности по предметам.
- `/tickets/random/` — сначала билеты с оценками «Не знаю»/«Плохо», затем уже выученные. Подготовка с таймером (по умолчанию 5 минут).
- `/timer/` — помодоро 25/5; досрочный перерыв не сбрасывает остаток работы. Состояние восстанавливается в том же браузере. Полностью завершённые сессии записываются в БД.
- `/timer/sessions/` — история собственных сессий, суммы и график по дням.
- `/accounts/` — профиль с изменением учебной группы; сервер принимает только существующую группу, которую администратор может изменить или создать в админке.

## Проверка

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

Для разработки в `requirements.txt` достаточно Django и драйвера PostgreSQL. Для production настройте HTTPS, `DJANGO_DEBUG=0`, постоянный `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` и статические файлы.

**Развёртывание, резервные копии, восстановление и Nginx:** подробная инструкция в [DEPLOYMENT.md](DEPLOYMENT.md).
